# AGENTS.md

Single source of truth for AI agents working in `helm-charts`.

## What this repo is

The Helm chart library for Tithely Kubernetes deployments. It is **not** a
deployed runtime service — it publishes packaged charts that other repos
consume. Charts:

- **`generic-service`** (`charts/generic-service/`) — the workhorse chart:
  frontend + worker deployments, cronjobs, migration jobs, services/ingress,
  autoscaling. Depends on the Bitnami `memcached` and `redis` subcharts.
- **`argocd-app`** (`charts/argocd-apps/`) — the equivalent for
  ArgoCD-deployed apps (schema differs from generic-service, e.g. `main:` vs
  `frontend:`).

On merge to `main`, **`chart-releaser`** (`.github/workflows/release.yaml`)
packages each chart and publishes it to the GitHub Pages Helm repo at
`https://tithely.github.io/helm-charts/`, tagged `<chart-name>-<version>`.
A merge to `main` publishes nothing until a release is cut.

## Care points (a chart change ripples to every consumer)

- Charts are consumed by `devops-cicd` (Flux HelmReleases) and `devops-argocd`
  (ArgoCD Applications), each **pinning a specific chart version**. A change to
  a chart reaches a service only when it is published *and* that service bumps
  its pin. A consumer's values must match the schema of the **pinned** version,
  not `main`. See the platform-atlas topic `chart-version-coupling-helm-cicd`.
- **`pre-commit` is mandatory and enforced.** After changing any chart's
  `Values.yaml` or `Chart.yaml`, run `pre-commit run helm-docs` to regenerate
  that chart's `README.md` before committing — the README is generated, never
  hand-edited. `checkov_secrets` and `checkov_diff` also run. Install with
  `pre-commit install` (see the repo `README.md`).
- Prefer minimal, reviewable changes. Mirror an existing chart's structure
  (e.g. a new `initContainer` block should match the frontend/worker pattern).

## Where things live

- `charts/<chart>/Chart.yaml` — chart metadata + version (the pinned version).
- `charts/<chart>/Values.yaml` — default values; the source helm-docs reads.
- `charts/<chart>/templates/` — the Go templates that render manifests.
- `charts/<chart>/README.md` — **generated by helm-docs** from `Values.yaml`
  + `Chart.yaml`. Do not edit by hand.
- `charts/<chart>/CHANGELOG.md` — Keep a Changelog; every behaviour change adds
  an entry.
- `charts/generic-service/CONTRIBUTING.md` — the authoritative versioning +
  release process for that chart (read it before bumping a version).
- `.pre-commit-config.yaml` — helm-docs + checkov + whitespace hooks.
- `.github/workflows/release.yaml` — chart-releaser publish pipeline.
- `repo-manifest.json` — repo metadata (owning team, lifecycle, purpose).

## Conventions (from `charts/generic-service/CONTRIBUTING.md`)

- **SemVer:** Patch = no change to rendered output; Minor = new *optional*
  values field (existing deployments unaffected); Major = breaking values-schema
  change.
- **Release process:** feature branches bump `Chart.yaml` to the next version
  with an `-rc.N` suffix; chart-releaser publishes it as a pre-release on merge.
  QA by pinning the RC in one service, then promote to the stable version in a
  `Chart.yaml`-only PR.
- **CHANGELOG:** add entries under `## [Unreleased]` (`Added` / `Changed` /
  `Fixed` / `Removed`); prefix breaking changes with `**Breaking:**`. On
  promotion to stable, move them into a dated version section with a compare
  link.
- **Follow Discuss, Plan, Confirm, Act** for any chart change — it affects live
  deployments downstream once consumers bump their pins.

## Doc layout note

Per-chart docs (`README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`) live under
`charts/<chart>/` by Helm convention and helm-docs generation — they are
intentionally **not** moved to a top-level `docs/`.
